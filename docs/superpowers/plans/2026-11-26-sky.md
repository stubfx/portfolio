# The Sky Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Luca prefers native execution). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the starfield and the world layers with one lowbit, dithered galaxy ("the sky"): an indexed framebuffer behind every page, a very soft reading lane, rare shooting stars, and worlds as palette fades.

**Architecture:**
- `src/client/sky-core.mjs` holds the pure, tested pieces: dither table, noise, ramp, lane falloff, quantization, twinkle and meteor steps.
- `src/client/sky.js` owns the canvas, the scroll and the schedule.
- `src/build/colour.mjs` mixes colours in sRGB and OKLab for the build.
- `src/build/world.mjs` now emits world colours as JSON.
- `src/client/world.js` maps `graph:current` to a sky palette.

**Tech Stack:** as before (Node 22 built-ins, vanilla ES modules and CSS, Python Playwright checks on the host's Chromium).

**Spec:** `docs/superpowers/specs/2026-11-26-sky-design.md` (binding), plus `2026-11-25-log-cards-design.md`.

## Global Constraints

- **Version control:** `gitt` only, as `luca` with no email (repo-local identity). Commit locally; push `main` when the task is done and the full suite is green (Luca asked for deploys).
- **Performance gates:** `perf.py --assert` at 1× CPU: no layout forced inside animation frames, no site script task over 4 ms. Home JS ≤ 25 KB gzipped.
- **Contrast:** AAA body text, AA labels, in every world.
- **Reduced motion:** a still sky. **No JS:** plain page. **Print:** no sky.
- **Leave alone:** the grain (Luca). Copy carries no em dashes.

## Review Focus

- Resizing the window (or rotating a phone) rebuilds the buffer and the lane without errors or a stale lane (Task 2, `sky-resize`).
- A very long page must not bake the whole sky up front: only rows on screen are built (Task 2, `sky-lazy` unit test).
- Returning to the top after a world must give the page's own palette, not a stale world (Task 3, `world-enters` merge leg).
- A project page must use its own palette, not the home's (Task 3, `sky-project-palette`).

### Task 1: Colour mixing and world data

**Files:** Create `src/build/colour.mjs`, `test/colour.test.mjs`. Modify `src/build/world.mjs`, `test/world.test.mjs`, `src/build/tokens.mjs` + `src/styles/tokens.css` (`lavender: '#b4befe'`).

**Interfaces:**
- `hexToRgb(hex) -> [r, g, b]`
- `rgbToHex([r, g, b]) -> '#rrggbb'`
- `mixSrgb(a, b, t)`: hex in, hex out. `t` is the share of `b`, as in `color-mix(in srgb, a (1-t), b t)`.
- `mixOklab(a, b, t)`: the same in OKLab.
- `worldPalettes(rows) -> [{ hashes: string[], base: '#rrggbb', accent: '#rrggbb' }]`, in order of first appearance; rows with identical colours share one entry.
  - Projects: `base = mixSrgb(TOKENS.base, palette.bg, .55)`, `accent = palette.accent`.
  - `big` rows: `base = mixSrgb(TOKENS.base, mixOklab(TOKENS.base, lane, .14), .55)`, `accent = lane`.
- `renderWorldData(rows) -> '<script type="application/json" id="worlds">…</script>'` or `''`.

**Tests:**
- `mixSrgb('#000000', '#ffffff', .5)` is `'#808080'`.
- `mixOklab` of a colour with itself returns it unchanged.
- `mixOklab('#000000', '#ffffff', 0)` is `'#000000'`.
- `worldPalettes` gives the fixture the expected shape and sharing.
- The home page carries `id="worlds"` with 7 worlds, and `e8d77f0` and `1a7c3e9` share one.

### Task 2: The sky renderer replaces the starfield

**Files:**
- Create `src/client/sky-core.mjs`, `src/client/sky.js`, `src/styles/sky.css`, `test/sky.test.mjs`.
- Modify `src/build/layout.mjs` (`<canvas id="sky">` replaces `<canvas id="stars">`), `scripts/build.mjs` (CSS_ORDER: `sky` after `world`), and `src/client/main.js`.
- Delete `src/client/stars.js`, `src/client/stars-core.mjs` and their test.

**Interfaces:**
- `sky-core.mjs`:
  - `bayer(n)`
  - `noise(seed)`
  - `fbm(n, x, y)`
  - `baseLevel(levels)`
  - `ramp(levels, base, accent)`: the level at `baseLevel` equals `base` exactly.
  - `laneFactors(width, left, right, fall, min)`
  - `quantize(v, levels, threshold)`
  - `twinkle(phase, group)`
  - `stepMeteor(m)`
- `startSky(canvas, { lane: () => [left, right] | null, colours: () => { base, accent } }) -> { tint(base, accent), meteor(), state() }`
  - `state()` returns `{ w, h, scale, coarse, tint: { base, accent }, target, fading, meteors, reduced }`, exposed as `__site.sky` for checks.

**Tests:**
- Unit: Bayer thresholds are a permutation in (0, 1); `ramp` is exact at the base level; `laneFactors` gives `min` inside, 1 far outside, monotonic between; `quantize` at an exact level is flat for every threshold; noise is deterministic; `sky-lazy`: building rows on demand never bakes more than the rows asked for.
- Browser:
  - `sky-renders`: canvas width ≈ viewport/3, `image-rendering: pixelated`, non-empty pixels.
  - `sky-lane-calm`: pixels in the lane at the text column have at most two distinct colours, and none is a star colour.
  - `sky-meteor`: `__site.sky.meteor()` adds a meteor; within 600 ms star-bright pixels appear outside the lane and never inside.
  - `sky-reduced`: two screenshots 800 ms apart are identical in the sky.
  - `sky-print`: the canvas is not displayed in print.
  - `sky-nojs`: without JS the canvas is transparent and there are no errors.
  - `sky-resize`: 1280 → 390 → 1280 without errors, and the lane follows.
  - The existing `texture` check reads the sky instead of `#stars`; `no-forced-layout` and `perf.py --assert` stay green.
